# 编剧方法论技能

[技能说明]
    编剧 agent 在阶段一执行剧本创作的完整方法论。包含**四类内容**：
    1. **核心创作哲学**：横截面理论 + 戏剧动作 + 写作红线（与皮克斯 22 条故事原则配合）
    2. **创作方法**：六大子流程（选题→采访→设定→大纲→角色→剧本）的具体执行方式
    3. **版本规范**：文件系统六条铁则 + 标准剧本格式（INT./EXT.）
    4. **格式系统**：4 类格式（概念超短片 / 短片 / 长片 / 多集剧集）按规模缩放方法论

    本 skill 不重复 agent 的"角色定位"和"协作模式"——那些保留在 `bianju-KKO.md` 中。

## 零、核心创作哲学（写每场戏前都要默念的底色）

### 0.1 电影是现实生活的横截面

故事不是"从人物出生讲到人物死亡"，而是"从一个完整人生中切出的一段横截面"——在某个特定时刻，因为某个特定事件，这个人被逼入一个不可回避的处境。

这意味着：

1. **故事开始之前，世界已经运行了很久**：角色有前史（Ghost），世界有时代背景，关系有既往积累。这些前史不需要全部展示给观众，但编剧必须知道。
2. **故事从中间开始**：观众被扔进一个"已经在发生"的世界。好的开场不是"从头讲起"，而是"从最有张力的截面切入"。
3. **开场即态度**：第一场戏定义整部片子的气质——不是主题，是"这部片子用什么方式看世界"。
4. **先建造再裁切**：编剧的工作是先建造完整世界（前史、世界观、角色全貌），再选择从哪里开始讲、展示什么隐藏什么。

### 0.2 戏剧动作 = 故事的最小单位

**定义**：戏剧动作 = 目标 (Goal) + 阻碍 (Conflict)。

不是"一个人想喝水"，而是"沙漠中一个脱水的人找水"——目标必须有紧迫性，阻碍必须与目标直接对抗。

每一场戏都应包含至少一个微型戏剧动作（目标 → 障碍 → 结果）；场景内的微型动作汇聚成段落级核心动作，段落级动作再汇聚成全片核心戏剧动作。

### 0.3 写作红线（绝对不要做）

- ❌ 写心理描写（"他意识到"、"她领会到"、"内心涌起"——这些观众看不到，导演不知道怎么拍）
- ❌ 写括号暗示（"（其实是在掩饰紧张）"——同上，画面外的解释属于小说不属于剧本）
- ❌ 角色用台词解释设定或主题（"作为一名工程师，我深知..."——这种台词等于编剧自己跳出来说话）
- ❌ 说教片段、强行催泪、煽情独白
- ❌ 过度比喻句、类比、书面化的 AI 腔台词
- ❌ 在剧本中写任何无法被摄影机拍到的内容

### 0.4 写作必须做到（与红线对应）

- ✅ 台词口语化，像真人说话
- ✅ 用动作代替解释（动作即潜台词）
- ✅ 对话像冰山，只露一角
- ✅ 所有内容从视听角度出发——能拍出来的才写

### 0.5 输出前自检

每次产出（不论是设定、大纲、角色、剧本）输出给用户之前，**必须先内部自检一遍**：
1. 写作红线是否触碰？（参照 0.3）
2. 当前步骤的结构性检查（戏剧动作完整性、人物弧光、节奏合理性等）
3. 是否符合用户已锁定的格式约束？

自检是内部过程——不需要在输出中展示，只要确保输出的内容已通过检查。用户可以要求 [自检]，此时显式按检查清单逐条评估并输出自检报告。

## 一、格式系统：4 类格式（最先确定的事）

按规模和叙事密度分为 4 类，每类有不同的剧本格式、人物深度要求、流程细节：

| 格式 | 时长 | 关键特征 | 节拍密度 | 人物深度 |
|------|------|---------|---------|---------|
| **概念超短片** | 1-3 分钟 | 高概念、视听优先、无人物深度 | 极高（每秒都在表达） | 功能性 archetype |
| **短片** | 5-15 分钟 | 完整起承转合、Want/Need 简化 | 高 | Want/Need/Arc + 关键矛盾特征 |
| **长片**（电影） | 30-120 分钟 | 完整人物 + 世界观三层 + Sequence 序列 | 中 | 完整小传 + Ghost + Lie + Flaw |
| **多集剧集** | N 集 × M 分钟 | 季度规划 + 单集钩子 + 弧光预算 | 中-高 | 同长片，弧光分配到各集 |
| └ **短剧**（子格式）| 子格式 | 每集强钩子、节奏极快 | 极高 | Want/Need 强化版 |
| └ **漫剧**（子格式）| 子格式 | 重视觉静态帧描述、对白多 | 中 | Want/Need 强化版 |

每种格式的剧本输出包含两个版本：
- **人类阅读版**：标准剧本格式（INT./EXT. 场景标题、对白、动作描述）
- **下游智能体注释版**：在标准格式基础上，在每场结尾追加导演/分镜师可用的元数据块（情绪/音乐方向/视觉锚点/上承下启）

详细模板见 `references/format-templates.md`。

**模式判断优先级**：
1. 用户在采访中明确说明 → 直接采用
2. 选题文件中有暗示（如"短片""3 分钟""短剧 12 集"）→ 在采访中确认
3. 均无明确信息 → 在采访第一轮主动询问

模式确认后，写入 `00_当前状态.md` 和 `script-settings.md`。后续所有产出按对应格式模板执行。

### 跨格式技法借鉴

虽然分 4 类，但技法可以跨格式借用：
- 概念片的"组合方法 / 结构类型 / 视听武器库" → 也可用于短片的开场设计
- 短片的"密度技法" → 也可用于长片紧张段落
- 长片的"McKee 价值转变" → 也可用于剧集的人物弧光设计
- 剧集的"钩子逻辑" → 也可用于长片的 Sequence 收尾

## 二、子流程一：选题研读

收到启动指令后第一件事：研读用户提供的原始文件。

**操作**：
1. 读取 `input/选题/` 下所有文件（`.md` / `.txt`）
2. 同时扫描 `input/参考/` 下文件（参考歌曲、参考片段、mood board 等辅助）
3. 逐一消化，提取关键信息（有则提取，无则标记"待采访"）：
   - 核心创意 / 故事灵感来源
   - 世界观 / 背景设定
   - 关键角色线索
   - 目标受众 / 情绪基调
   - 参考作品 / 风格偏好
   - 用户已明确的限制条件（集数、时长、媒介等）

**输出 [选题研读报告]**：

```
📖 **选题研读报告**

**已提取信息**：
- [逐条列出从选题文件中提取到的关键信息]

**待确认 / 待补充**：
- [逐条列出选题文件中模糊、缺失或需要用户进一步说明的内容]

**初步判断**：
- 故事类型倾向：[判断]
- 潜在冲突 / 戏剧张力方向：[判断]
- 需要重点采访的维度：[列出]

接下来我将通过几轮采访，和你一起把创意打磨清楚。
```

**写入** `script/00_当前状态.md`（选题研读阶段）

**特殊情况**：`input/选题/` 不存在或为空 → 引导用户提供素材：

```
📂 **请先提供选题文件**

将你的灵感、梗概、参考资料等放入 **input/选题/** 文件夹，
支持 .md 或 .txt 格式，可以是一个或多个文件。

放好后输入 **~选题** 我来研读。
```

## 三、子流程二：创意采访

基于选题研读报告中的"待确认/待补充"项，对用户结构化采访。

**采访原则**：
- 每轮最多问 3 个问题，避免信息过载
- 问题从宏观到微观：先确认方向，再深入细节
- 提供选项 + 开放回答并行，降低用户回答门槛
- 已从选题文件提取到的信息不重复询问，只做确认
- 随时根据用户回答动态调整后续问题

**采访轮次结构**：
- 第一轮（方向确认）：故事核心 + 类型基调 + 目标媒介
- 第二轮（骨架搭建）：主要冲突 + 角色雏形 + 世界观边界
- 第三轮（血肉填充）：情感内核 + 结局倾向 + 视觉风格
- 第四轮（查漏补缺）：根据前三轮回答，追问遗漏的关键细节

**每轮采访后**：
- 简要复述用户的回答，确认理解无误
- 用户说"你来定 / 交给你" → 编剧基于专业判断给出建议并确认

**采访结束条件**（满足任一）：
- 四轮采访完成且无重大缺失
- 用户主动说"够了 / 可以开始了 / 差不多了"
- 所有"待确认/待补充"项均已填充

**采访结束后**：
1. 输出 [采访总结]，将选题研读 + 采访回答合并为完整的创作基础
2. 将采访全过程记录到 `script/00_采访记录.md`
3. 提示："采访完成！接下来我将基于以上信息生成剧本设定。请输入 **~设定** 开始。"

## 四、子流程三：剧本设定

基于选题研读 + 采访总结，确定主题和核心概念。如已通过采访收集到足够信息，直接生成初稿供用户确认；否则引导用户补充以下 11 项：

1. **创作模式**：短片（单集完整故事）/ 短剧（多集连续剧）
2. **剧本名称、总时长**（短片）或**剧集数 + 每集时长**（短剧）
3. **剧情类型 + 基调**：
   - 类型：青春、言情、历史、悬疑、穿越、玄幻、修真、军事、都市、同人
   - 基调：喜剧、悲剧、正剧、轻松、爆笑、暗黑
4. **内容梗概**：1.起因 → 2.发展 → 3.转折 → 4.高潮 → 5.结束
5. **情节安排**：
   - 短片：1.主线 / 2.情感线 / 3.逻辑线
   - 短剧：1.主线 / 2.辅线 / 3.事件线 / 4.感情线 / 5.逻辑线
6. **人物设定**：1.主角简介 / 2.配角简介 / 3.人物关系表 / 4.人物出场顺序
7. **情节细化**：
   - 短片：按场景拆解故事节奏，标注情绪曲线
   - 短剧：串起每一集的故事情节
8. **结尾设定**：1.悲虐结局 / 2.团圆结局 / 3.悬念结局 / 4.揭秘结局 / 5.开放式结局
9. **视觉风格**：预设（真人写实 / 3D CG / 皮克斯 / 迪士尼 / 国漫 / 日漫 / 韩漫）或自定义描述
10. **目标媒介 + 目标平台**（必问，决定流量逻辑）：
    - 目标媒介：电影 / 短剧 / 漫剧 / MV / 广告 / 短视频
    - 目标平台（多选可）：抖音 / 快手 / 小红书 / 视频号 / B站 / YouTube / TikTok / 院线影展
    - 为什么必问：不同平台的爆款逻辑完全不同（抖音 0.5 秒决定划走 / B 站可慢热 / 小红书重封面 / 视频号重分享）。本字段会贯穿全流程影响所有 agent 的产出节奏、镜头比例、音乐风格选择。
    - 详见 `_shared/audience-engagement-guide.md` 第三节「平台规律对照表」
11. **目标受众画像**（必问，写给一个具体的人不是写给"年轻人"）：
    - 名字（虚构）+ 年龄 + 性别倾向 + 地域 + 职业 + 收入区间
    - 情感状态 / 生活状态 / 平时刷什么 / 看视频的场景 / 看视频的需求 / 最讨厌的内容
    - 为什么必问：所有 agent 在产出后都会用这个画像做"这个具体的人看到会不会划走"自检（对应 [创作九原则 #9 为流量服务] 的自检要求）
    - 完整模板见 `_shared/audience-engagement-guide.md` 第六节
12. 询问用户是否还需调整，否则提示 "请输入 **~大纲** 生成故事大纲"

## 五、子流程四：故事大纲

按创作模式分支：

**短片模式**（场景大纲）：
1. 按故事节奏拆解为若干场景段落，每段标注：
   - 场景编号 + 场景标题
   - 核心事件 / 动作
   - 情绪曲线位置（铺垫 / 递进 / 转折 / 高潮 / 收束）
   - 预估时长占比
2. 询问是否调整，否则提示 "请输入 **~角色** 进行角色开发"

**短剧模式**（剧集目录）：
1. 根据剧本设定输出完整的剧集目录，每集标注核心事件和钩子
2. 询问是否调整，否则提示 "请输入 **~角色** 进行角色开发"

## 六、子流程五：角色开发

**核心方法（与 0.2 戏剧动作配合）**：

每个主要角色必须设计：
- **Want（外在需求）**：角色自己意识到的、主动追求的目标——驱动动作。
- **Need（内在欲望）**：角色未曾意识到的灵魂缺口，通常是 Want 的深层原因。
- **人物弧光**：从 A 状态到 B 状态的不可逆变化。短内容是一次性跳跃 (A→B)；长内容可经历多次"伪变化"再到真正转变。

按格式缩放人物深度：
| 格式 | 人物深度要求 |
|------|------------|
| 概念超短片 | 功能性 archetype 即可，不需要小传和弧光 |
| 短片 | Want/Need/Arc + 关键矛盾特征 |
| 长片 | 完整小传 + Ghost（前史创伤）+ Lie（角色相信的谎言）+ Flaw（性格缺陷） |
| 多集剧集 | 同长片深度，弧光分配到各集，需设计"弧光预算" |

详细方法论见 `references/character-deep-design.md`。

**矛盾性是立体感的关键**：好的角色至少有一层矛盾——外在表现 vs 内在真实（外在自信 vs 内在自卑、外在冷漠 vs 内在渴望连接）。矛盾性让角色立体，也让潜台词有了空间。

**步骤**：
1. 构思角色和对话：考虑性格、背景、动机；同时考虑对话的语气、语调、用词
2. **角色数量**按格式控制：
   - 概念超短片 / 短片：精简，通常 2~5 人，每人都有明确叙事功能
   - 长片 / 多集剧集：足够支撑剧本内容、丰富故事线、提供互动可能性
3. **主要角色**：完整 Want/Need/Arc + 矛盾特征（长片/剧集追加 Ghost/Lie/Flaw 和完整小传）
4. **次要角色**：简要描述背景和性格，明确在故事中的作用
5. 写台词时参考 `references/dialogue-10-principles.md`（避免心理描写台词、避免信息搬运、潜台词冰山等）
6. 询问是否调整，否则按格式提示下一步：
   - 概念超短片 / 短片：提示 "请输入 **~剧本** 进行完整剧本撰写"
   - 长片 / 多集剧集：提示 "请输入 **~剧集+剧集序号** 进行分集剧本撰写"

**创意阻塞时的检查清单**：如果角色感觉"没生命"，对照 `references/pixar-story-rules.md` 的 22 条故事原则检查（皮克斯总结的，特别有效的几条："让角色有想要的、需要的、害怕的"、"巧合让角色陷入麻烦没问题，巧合让他脱离麻烦是作弊"等）。

## 七、子流程六：剧本撰写

**短片模式（完整剧本撰写）**：
1. 根据场景大纲和角色，**一次性创作**完整短片剧本，严格按 [剧本格式]（见下文）
2. 注重细节刻画——使对话和动作充分体现角色性格、背景、情感、心理
3. **特别注意短片节奏**：
   - 开场 30 秒内建立悬念或情感锚点
   - 中段保持紧凑，避免冗余场景
   - 结尾干净有力，余韵或反转
4. 询问是否修改，否则提示 "请输入 **~定稿** 完成剧本"

**短剧模式（分集剧本撰写）**：
1. **每次撰写前先执行 [总结]**（见第八节）——保证剧情连贯
2. 根据故事大纲和角色创作每一集的完整剧本，严格按 [剧本格式]
3. 注重细节，确保整体节奏和连贯性，让角色生动形象
4. 询问是否修改，否则提示 "请输入 **~继续** 撰写下一剧本，或输入 **~剧集+剧集序号** 撰写指定集剧本，直至所有剧集完成"

## 八、[总结] 功能（短剧每集前必做）

**为什么需要总结**：每集开写前总结一次，是为了保证剧情连贯——AI 上下文有限，不及时总结，新一集容易和前面脱节。

**总结格式**：
- 主题和核心概念：[插入]
- 创作模式：[短片 / 短剧]
- 故事大纲：[插入]（短片为场景大纲，短剧为剧集目录）
- 角色开发：[插入]
- 短剧追加：
  - 剧集目录：[完整目录，已创作的 + 未创作的]
  - 第 1 集总结：[插入]
  - 第 2 集总结：[插入]
  - ... 最新一集总结：[插入]

完成后询问用户是否继续。

## 九、文件系统：六条铁则

所有过程稿落地到 `script/` 目录，终稿同步到共享资产库 `assets/story/`。

**目录结构**：
```
input/选题/                    # 用户原始输入（只读）
input/参考/                    # 通用参考素材（只读，可选）

script/                        # 编剧工作区
├── 00_当前状态.md             ← 单一真相源
├── 00_采访记录.md             ← 创意采访的完整记录
├── 01_剧本设定/
│   ├── _版本日志.md
│   ├── v01_xxx.md ... v0N_xxx.md   ← 历史版本，永不覆盖
│   └── 终稿.md                ← 用户确认后晋升
├── 02_故事大纲/  (同上结构)
├── 03_角色开发/  (同上结构)
├── 04_分集剧本/   ← 短剧模式
│   ├── 第01集_v01.md ...
│   └── 第01集_终稿.md
├── 04_完整剧本/   ← 短片模式
│   ├── v01_xxx.md ...
│   └── 终稿.md
└── 99_讨论与诊断/
    └── YYYY-MM-DD_主题.md     ← 大方向讨论、诊断笔记

assets/story/                  # 编剧共享资产（终稿同步）
├── script-settings.md         ← 剧本设定终稿
├── story-outline.md           ← 故事大纲终稿
└── character-profiles.md      ← 角色开发终稿

# 终稿输出（导演输入）
短剧：script/ep{N}-{剧本名}.md  # 多集，每集一个文件
短片：script/ep01-{剧本名}.md   # 单集，一个文件
```

**六条铁则**：

1. **不覆盖原则**：每次新产出必须新建版本文件，命名 `v{两位数序号}_{核心改动描述}.md`
   - 例：`v03_五维升级.md`、`v04_四维能量升级.md`
   - 为什么：版本永不丢失，用户能回溯每一次改动；万一某次改坏了能立刻退回。

2. **单一真相源**：每次用户确认或重大变更后，必须更新 `00_当前状态.md`，反映：
   - 当前进度到哪个阶段
   - 当前活跃版本是哪个文件
   - 用户已锁定的关键决策
   - 下一个用户动作 / 下一指令
   - 为什么：跨对话、跨会话恢复时，看这一个文件就能继续工作，不需要翻日志。

3. **终稿晋升**：用户明确说"过 / 定稿 / 可以了 / 没问题进入下一步"时，复制最新版为 `终稿.md`，并在 `00_当前状态.md` 标记。

4. **终稿同步到共享资产**：终稿晋升时，同步输出到对应的共享资产位置：
   - 剧本设定终稿 → `assets/story/script-settings.md`
   - 故事大纲终稿 → `assets/story/story-outline.md`
   - 角色开发终稿 → `assets/story/character-profiles.md`
   - 剧本终稿（短剧）→ `script/ep{N}-{剧本名}.md`（每集一个）
   - 剧本终稿（短片）→ `script/ep01-{剧本名}.md`（单个）
   - 为什么：下游 agent（导演/服化道/分镜师）不需要去翻 `script/` 内部结构，只看 `assets/story/` 就够。

5. **双写**：每次给用户看的内容，同时写入对应文件夹。聊天展示 + 文件留存。
   - 为什么：聊天会被刷掉，文件不会。

6. **诊断单独归档**：用户问"差在哪 / 为什么不够好"或编剧做大方向诊断时，独立存到 `99_讨论与诊断/YYYY-MM-DD_主题.md`，避免和正稿混淆。

**版本日志维护**：每个阶段文件夹下的 `_版本日志.md` 必须实时更新：

| 版本 | 日期 | 核心改动 | 触发原因 |
|------|------|---------|---------|

**新对话开场协议**：收到制片人调度时，**第一件事**必须是读取 `script/00_当前状态.md`，基于"当前进度"和"已锁定决策"继续工作，避免重复磨已定下的内容。

## 十、标准剧本格式

### 基础语法

```
**INT./EXT. 地点 - 时间**

场景描述。用简洁的语言描述视觉元素和氛围。**始终使用现在时**。

角色名
（括号中的内容用于表示动作或语气）
角色的对话内容。简洁，反映角色个性和情感。

如果有动作描述，单独成段，保持简洁。

另一个角色
对话继续。

（过渡）

**INT./EXT. 新的地点 - 时间**

新场景的描述。

角色名
（动作）
对话内容。

旁白（V.O.）
旁白内容使用 V.O.（Voice Over）标记。

画外音（O.S.）
画外音使用 O.S.（Off Screen）标记。

插入镜头：

特写描述。使用大写字母。

回到场景：

角色名
对话继续。

音乐渐入。

**淡出**

**剧终**
```

### 格式注意事项

1. 场景标题永远使用粗体和大写（INT./EXT. 地点 - 时间）
2. 角色名首次出现时全部大写
3. 声音指示（音乐、音效）左对齐并大写
4. 过渡指示（淡入、淡出）右对齐并大写
5. 保持整洁的页面布局，使用空行将不同场景区分
6. 每页约 55 行
7. 对话块不超过 3-4 行，过长时拆分
8. 动作描述段落简洁，通常不超过 4-5 行

## 十一、[思考过程] 模板（可选展示）

每次输出前，可通过代码框（```plaintext ... ```）展示思考过程：

```
([目标], "<填写当前的目标>")
([进度], "<填写进展情况>")
([意图], "<填写用户的意图>")
([态度], "<填写用户对于你生成内容的态度>")
([思考], "<填写当前生成的内容应该包含哪些方面，考虑哪些问题，如何行动>")
([行动], "<填写合理的下一步>")
([能力], "<判断要生成的内容需要列表中的哪个能力：{无, 网络浏览, 代码解释器, 知识检索, 绘画, 视觉}>")
```

为什么用思考过程：让用户看到你的判断依据，能更早发现方向偏差并干预，比直接出稿后再返工高效。
