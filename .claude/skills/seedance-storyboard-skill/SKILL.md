# Seedance 2.0 分镜编写技能（v7.0 双轨模式）

[技能说明]
    将导演的讲戏内容转化为 Seedance 2.0 格式的动态视频提示词。本技能支持两种模式：
    - **故事板模式**（v7.0 新增）：每个剧情点 P0X 生成 1 张「万能故事板 PNG」（含角色/场景/分镜/辅助信息），视频提示词以 @P0X-storyboard.png 单图引用。
    - **单镜模式**（沿用 v6.1）：视频提示词直接引用 character/scene/prop 多张 PNG。

    无论哪种模式，每个剧情点 = 一段完整叙事 = 多个 Cut（Cut 1-N，5-8 默认 / ≤12）。

[锁/变分层法]（v12.0 新增 · 写提示词的第一步思考框架）

    **每写一条 Cut 之前，先在脑内分两层**（不进产物格式，只是组织信息的方式）：

    **恒定层**（跨镜不变）→ 用 @图片引用解决，不在文字里重复描述
    - 角色的外貌、服装（已在 character-prompts.md 精确定义）
    - 场景的环境、布局（已在 scene-prompts.md 精确定义）
    - 全片视觉风格基准（嵌入【氛围与画质】，从 creative-brief.md 复制）

    **可变层**（这一镜独有）→ 写进【画面内容】
    - 这个镜头里，人物做了什么具体动作
    - 镜头如何运动（景别切换、推拉摇移）
    - 情绪有什么变化（上一秒到这一秒的差异）

    **自检**：写完后问"这段文字里，有没有重复描述 @引用图片里已经固定的外观？"
    → 有 → 删掉重复描述，只保留动作和运镜
    → 没有 → 继续

    ⚠️ 注意：锁/变分层是减少冗余文字的原则，不等于"省略参考图"。
    心智透明原则（每 Cut 必须带场景 @引用）依然有效——只是用 @图片 代替文字描述。

[执行流程]

    第一步：读取上游产物
        - 读取导演讲戏本（01-director-analysis.md）
        - 读取人物提示词（assets/visual/character-prompts.md）
        - 读取场景提示词（assets/visual/scene-prompts.md）
        - 读取关键道具提示词（assets/visual/prop-prompts.md，如存在；不存在或本集无道具则跳过）
        - 读取音乐设计方案（assets/music/music-design.md，如存在，提取 M01/M02 编号作为后期配乐参考标记，**不写入提示词正文**——见 [严禁视频音乐红线]）
        - 读取项目设置（settings.visual_style / settings.aspect_ratio）
        - **🔴 读取 .project-config.json.video_model_config（v8.0 硬约束，必读）**：
            - 读取 `primary_model`（用于在 episode-master.md 中标注）
            - 读取 `max_seconds`（单 Cut 最大时长，全局硬约束）
            - 读取 `min_seconds`（单 Cut 最小时长，默认 4）
            - **读取能力标志（v11.0 新增）**：
                - `supports_image_ref`：能否上传图片做参考（I2V）；false 则所有 Cut 均为 T2V
                - `supports_video_ref`：能否上传视频做续接（V2V）；false 则禁用 V2V 模式
                - `supports_audio_ref`：能否上传音频做参考；true 时才在上传清单中加音频槽位
            - 如 .project-config.json 不存在或字段缺失 → **停下来告知用户**：「分镜阶段需要知道你用的视频模型和能力，请先执行 ~video-model 配置」，等用户回答后写入配置再继续
            - 永远不要自己猜测 max_seconds —— 猜错导致用户所有提示词时长超限，直接废掉
        - **🔴 读取 .project-config.json.image_model_config（v11.0 新增，必读）**：
            - 读取 `primary_model`（生图工具名，用于用户操作提示）
            - 读取 `grid_mode`（宫格布局：single / 2x3 / 2x4 / 3x3 / 自定义）
            - 如字段缺失 → 停下来告知用户：「故事板阶段需要知道你用的生图工具和宫格偏好，请先执行 ~image-model 配置，或直接告诉我：1）你用哪款生图工具？2）想要单张模式还是几宫格（2x3 / 2x4 / 3x3）？」，等用户回答后写入配置再继续
            - `grid_mode` 直接影响故事板提示词结构：single = 每 Cut 独立一份提示词文件；NxM = 每 P0X 一份宫格复合提示词
        - 读取 seedance-prompt-methodology.md
        - 读取 examples/seedance-prompt-examples.md，了解官方提示词的风格和结构
        - **如本集是续集（ep02+），读取上一集 `outputs/<前集>/episode-master.md` 的 `§9.3 给下一集的核心交接` 段（恒定 8 字段）**——不读全文，仅读这一段，避免 N 集累积导致信息过载（v7.0.2 跨集累积风险防御）

    第二步：判定模式（双轨选择）
        见 [双轨模式判定]。判定结果通过【模式选择】段告知用户。

    第三步：分支执行
        - 故事板模式 → 走 [故事板模式流程]
        - 单镜模式 → 走 [单镜模式流程]

    第四步：输出 episode-master.md
        所有 P0X 写完后，按 templates/episode-master.template.md 输出全片总览（双模式都要）。

[双轨模式判定]

    判定优先级（自上而下，命中即停；**字段不存在 → 跳过本级进入下一级**，不要报错）：

    1. 用户单集锁定（最高优先级）
       - 读 `.project-config.json.storyboard_overrides[<当前集数>]`，存在且值 ∈ {"storyboard", "single-shot"} → 直接采用
       - 字段不存在 / `.project-config.json` 不存在 / `storyboard_overrides` 整段不存在（v6.1 老项目）→ 跳过本级，进入第 2 步
       - 例：storyboard_overrides.ep01 = "storyboard" → ep01 整集走故事板模式

    2. 用户全局锁定
       - 读 `.project-config.json.storyboard_overrides.global`，存在且值 ∈ {"storyboard", "single-shot"} → 直接采用
       - 字段不存在 → 跳过本级，进入第 3 步

    3. 导演「建议形态」字段
       - 讲戏本中每个 P0X 给出「建议形态：故事板 / 单镜 / 随他」
       - 「随他」或字段缺失 → 跳过本 P0X，进入第 4 步
       - 「故事板」或「单镜」 → 采用导演建议（按 P0X 粒度，可以同一集中混合）

    4. AI 自动判定（fallback，永远兜底）
       - 多镜头蒙太奇 / 节奏密集 / 群戏 / 多机位切换 → 故事板模式
       - 单一画面 / 长镜头 / 抒情慢镜 / 单角色独白 → 单镜模式
       - 不确定时 → 故事板模式（一般情况下故事板模式视觉一致性更强）

    AI 必须主动告知用户：

        【模式选择】
        本片采用 <故事板模式 / 单镜模式 / 混合模式>
        判定理由：<具体理由，注明命中第几优先级>
        如需切换请用：~storyboard-mode <storyboard / single-shot> [<集数 / global>]

[故事板模式流程]（v7.0 新增）

    1. 风格决策（读 references/storyboard-style-decision-tree.md）
       - 4 维度判定（用户偏好 → 题材 → 复杂度 → settings.visual_style）
       - 输出风格名（5 候选之一：cinematic_realism / disney_3d_animation / epic_realism / commercial_clean / black_white_manga_lineart）
       - AI 主动告知：

            【故事板风格判定】
            本片故事板风格 = <风格名>
            判定理由：<维度 X 命中——具体理由>
            如需覆盖请用：~storyboard-style <名>

    2. 模块组合判定（读 references/universal-storyboard-methodology.md §四）
       - 必备 6（M1-M6）
       - 可选 4（O1 场景状态图组 / O2 关键道具 / O3 对白气泡 / O4 十六进制色板）按场景挑选

    3. 写《故事板提示词文件》（按 image_model_config.grid_mode 决定结构，**必须先读取配置**）

       **grid_mode = "single"（单张模式，质量最佳）**：
       - 每个 Cut 单独生成一份提示词文件，输出路径：`outputs/<集数>/storyboards/P0X-CutN-storyboard-prompt.md`
         （例：P01-Cut1-storyboard-prompt.md / P01-Cut2-storyboard-prompt.md / ...）
       - 每份文件只描述该 Cut 的单帧画面：风格段 + 构图 + 角色 + 情绪 + 光照 + 画幅，无需宫格排版段
       - 文件命名规范：`P{N}-Cut{M}-storyboard-prompt.md`，P 编号与导演讲戏本 P0X 对齐，Cut 编号与 video-prompts.md 对齐
       - 为什么质量更好：生图模型专注单帧，不分散注意力给多个格子，细节与一致性显著提升

       **grid_mode = "2x3" / "2x4" / "3x3" / 自定义 NxM（宫格复合模式）**：
       - 输出路径：`outputs/<集数>/storyboards/P0X-storyboard-prompt.md`（每 P0X 一份，沿用原有命名）
       - 每个 P0X 一份完整提示词文件（基于 references/universal-storyboard-methodology.md 的写作铁律）
       - 单文件内含 YAML 头部（M6 衔接 frontmatter）+ 核心目标段 + 整体风格段 + 画面结构段 + M1-M6 + 选用 O 模块 + 限制段 + 画幅排版段
       - 在【画幅与排版】段明确写出宫格配置（例：「请将本 P0X 的 Cut 按 2列×4行 布局排列，每格一个 Cut 的定格画面」）
       - ⚠️ 宫格质量提示：若本 P0X 镜头数 > 宫格格数，提示用户考虑拆 P0X 或改用 ~image-model 切换单张模式
       - 长度参考：完整版 800-1500 字 / 精简版 500-800 字 / 超长警戒 > 1800 字时砍 M3
       - **故事板大图（复合图）默认 16:9 横版**（信息密度最大化）。但**最终视频画幅** = `settings.aspect_ratio`。在【画幅与排版】段必须同时写明这两点，避免 AI 把故事板大图也画成 9:16（会塞不下信息）

    4. 衔接机制（读 references/transition-mechanism.md）
       - 每个 P0X 的 YAML 头部填 from_previous + to_next 字段（5 维度信息）
       - 内容来自导演讲戏本的前后剧情点描述，前期一次性设计完
       - 首段填「无（开场）」、末段填「无（结尾）」

    5. 写《视频提示词表》video-prompts.md（故事板模式专用结构）
       - 每个 Cut 一行，列：Cut / 剧情点 / 时长 / 焦距 / 景别 / 运动 / **素材引用 / 描述 / 对白 / 承接 / 音乐编号**
       - **素材引用列**：仅 1 张 @P0X-storyboard.png（不再分散引用 character/scene/prop）
       - 🔴 **时长硬约束（v8.0 核心修复）**：
         - 每个 Cut 标注时长必须 ≥ `video_model_config.min_seconds`（默认 4s）
         - 每个 Cut 标注时长必须 ≤ `video_model_config.max_seconds`（从 .project-config.json 读取，绝对不能超）
         - 单 P0X 总时长 ≈ `max_seconds` ± 2s（随 max_seconds 动态变化，不再写死 15s）
         - 为什么是硬约束：提示词时长超限→用户去生成工具操作时发现不支持→整段提示词废掉→全部重写。这是最常见也最浪费时间的错误。
         - 时长精确到 0.1 秒（如 3.5s / 4.0s / 6.8s）
         - 写完后自检：扫描所有 Cut 时长，如有任何一个 > max_seconds，立即修正再输出
         - 🔴 **心智透明自检（v11.0 新增，每个 Cut 写完后必做）**：
           视频生成工具是零上下文的陌生人——它只能看到你给它的东西，不知道任何剧情背景。
           每个 Cut 写完上传清单后，立即执行以下核对：
           1. 扫描该 Cut 的【画面内容】，找出所有**出现在画面里的具名角色**（包括配角、反派、第二主角）
           2. 对照上传清单，确认每个具名角色的参考图都已列入（character-xxx.png）
           3. 如有遗漏：补入对应参考图到上传清单，并在【参考设定】里补一行说明
           4. 群演/无名路人 → 不需要参考图，在【画面内容】里用文字描述即可（"背景有数名百姓"）
           常见遗漏场景举例：
           · "双人对切"镜头 → 两个角色都要上传，不只是说话的那个
           · "陈稳看着赵克用离开" → 陈稳也在画面里，不能只传赵克用
           · "众人围观" + 主角反应 → 主角参考图要传，群演文字描述即可
         - 🔴 **隐性跨镜引用自查（v11.0 新增）**：
           扫描【氛围与画质】和【画面内容】，检查有没有"引用其他角色或其他镜头来解释本镜视觉意图"的写法。
           视频模型单镜处理，不知道其他 Cut 发生了什么，也不认识任何角色。
           凡是出现以下类型写法，必须改写为自洽的视觉意图：

           ❌ 有问题（依赖外部上下文）：
           · "与赵克用的仰拍形成视角对比" → 模型不知道赵克用、不知道其他 Cut
           · "延续上一个镜头的紧张氛围" → 模型不知道上一个镜头
           · "配合前文陈稳的崩溃情绪" → 模型无法关联前文

           ✅ 正确改写（视觉意图自洽）：
           · "俯拍陈稳，偏高镜头强化其弱势感和被审视的压迫感"
           · "维持冷蓝色调，演员表情保持紧绷"
           · "陈稳神情失控，手抖"

           自检方式：问"如果这是唯一一个 Cut，这段描述能让模型执行出正确画面吗？" 不能 → 补信息。
       - 🔴 **画幅锁定铁律（v7.0.2 防传染机制）**：
         - 表上方必须加全局声明：「**本集所有 Cut 视频画幅 = `settings.aspect_ratio = <实际值>`**，不论参考图（含 16:9 横版的 P0X-storyboard.png）画幅如何。Seedance 生成时**用户必须在工具里手动选此画幅**。」
         - 每条 Cut 的「描述」列**开头**必须写画幅指令，格式如「[9:16 竖版构图，垂直运动重心] <动作描述>」（防 Seedance 看到 16:9 参考图就默认输出 16:9）
         - 为什么必填：故事板复合图永远 16:9（信息密度），但项目可能是 9:16 / 1:1 / 21:9 等。如果不显式写画幅，Seedance 会"参考"故事板的 16:9 → 与 settings.aspect_ratio 错位 → 视频废
       - 编号格式：Cut 1 / Cut 2 / ... / Cut N（不用 P<X>.1 至 P<X>.<n>）
       - 默认 5-8 镜，上限 12 镜，超 12 拆为 P0X.A + P0X.B（衔接字段套用）

    6. 用户操作提示（写入 episode-master.md 的「用户操作清单」段，不要写到单个 P0X-storyboard-prompt.md 里）

       **单张模式（grid_mode = "single"）时**：
        【用户操作】
        1. 逐个打开 outputs/<集数>/storyboards/P0X-CutN-storyboard-prompt.md，复制全文去 <image_model_config.primary_model> 生成对应 Cut 的单帧参考图
        2. 归档到 outputs/<集数>/storyboards/P0X-CutN-storyboard.png（与 -prompt.md 配对）
        3. 拿视频提示词表 outputs/<集数>/video-prompts.md 去 <video_model_config.primary_model> 逐 Cut 生视频
        4. 用剪辑工具串接所有 Cut

       **宫格模式（grid_mode = NxM）时**：
        【用户操作】
        1. 逐个打开 outputs/<集数>/storyboards/P0X-storyboard-prompt.md，复制全文去 <image_model_config.primary_model> 生成万能故事板 PNG
        2. 归档到 outputs/<集数>/storyboards/P0X-storyboard.png（注意是 .png，与 -prompt.md 配对）
        3. 拿视频提示词表 outputs/<集数>/video-prompts.md 去 <video_model_config.primary_model> 逐 Cut 生视频
        4. 用剪辑工具串接 Cut 1...Cut M

[单镜模式流程]（v10.0 三块散文格式 + 上传清单）

    **v10.0 升级：三块散文结构 + 小白友好上传清单并存。**

    「三块散文」的设计哲学（来自 Seedance 分镜师2.0）：
    - 【参考设定】：每个 @素材先一句话说明用途，再标文件名。角色外观交给设定图，不重复描述。
    - 【氛围与画质】：承接 `creative-brief.md` 的全片视觉风格基准段，跨所有 Cut 复用这一块，不用每条重写。
    - 【画面内容】：只写"动"——具体物理动作 + 运镜。恒定信息（外观/风格）不在这里重复。

    **可跟随性原则（followability > completeness）**：
    模型跟不住的细节宁可删，不硬塞。单镜50-70词就够，短而可跟随比长而完整更有效。
    分镜头序列靠「镜头N」标签分段，每段紧凑，整条可以更长。

    1. 读取上游材料
        - 读取 assets/visual/ 了解所有可用的角色/场景/道具 PNG 文件名
        - **读取 assets/story/creative-brief.md 的「全片视觉风格基准段」**——将逐字嵌入每条【氛围与画质】
        - 了解哪些人物是群演/一次性配角（直接文字描述，不上传参考图）

    2. 判断每个 Cut 的生成模式（T2V / I2V / V2V）

        **必须先读取 video_model_config 的能力标志，再决定模式**：

        | 模式 | 前提条件 | 适用场景 |
        |------|---------|---------|
        | **T2V**（文本转视频） | 无前提，任何工具都支持 | 画面中**完全没有具名角色**（纯环境/纯特效/纯UI）|
        | **I2V**（图像转视频） | `supports_image_ref=true` | 画面中有具名角色 → **优先选这个，角色一致性最强** |
        | **V2V**（视频续接） | `supports_video_ref=true` | 上一段已生成，做帧级连续续接（后期精修专用） |

        ⚠️ `supports_image_ref=false` 时：所有 Cut 强制 T2V，不生成上传清单（工具不支持传图）
        ⚠️ `supports_video_ref=false` 时：V2V 模式禁用，续接段落改用 I2V 或 T2V

        🔴 **T2V 判定红线（v11.0 修复，来自真实崩坏案例）**：
        只要画面中有具名角色出现，**无论叠加了多少特效/UI**，都必须用 I2V 上传角色参考图。
        特效和UI是叠在角色上面的一层，不会让角色消失——没有参考图，视频模型会凭空捏造一个和原设计毫无关系的人脸。

        ❌ 错误判断："这个Cut以数据视界UI效果为主，所以T2V无需上传角色参考图" → 生成出来的角色面目全非
        ✅ 正确判断："赵克用在画面里（透过UI叠层可见），所以I2V，传赵克用参考图 + 在提示词里描述UI效果"

        只有以下情况才能真正用T2V：
        - 纯环境镜头（无任何具名角色）
        - 纯UI/特效全屏（无角色出现，包括背景）
        - supports_image_ref=false（工具本身不支持传图）

[Seedance 2.0 提示词写法核心规则]（双模式通用）

    叙事描述式
        - 用完整的导演式段落描述，不要关键词堆叠
        - Seedance 2.0 擅长理解长段叙事性提示词
        - 参考官方模板风格：连续段落，包含运镜、动作、光影、声音的融合描述

    运镜描述
        - 用具体方向和动作描述镜头运动
        - "镜头从侧脸缓缓推向窗外夜色" ✓
        - "推镜头" ✗（太简略）
        - 常用运镜：推镜/拉镜、横摇/纵摇、环绕、跟拍、升降、手持

    动作描述
        - 用具体的物理动作，避免抽象概念
        - "她揉了揉太阳穴，目光从屏幕移开，靠向椅背" ✓
        - "她感到疲惫" ✗

    时长控制
        - 遵循导演建议的时长
        - 每个剧情点的动作/内容密度与导演建议的时长匹配
        - 单 Cut 最短 1.2s，最长不限（但 Seedance 单次输出 ≤ 15s）
        - 单 P0X 总时长 ≈ 15s ± 2s

    声音/台词（**严禁背景音乐！** 详见 [严禁视频音乐红线]）
        - **🔴 台词类型必须区分（v11.0 新增）**：
          "对白"对视频模型意味着"角色开口说话"——它会生成嘴唇动作。
          内心OS是角色不开口的内心独白，后期才配音。用错标签会让角色"嘴动了"，画面废掉。

          五种类型，核心判断依据是"视频模型是否需要生成嘴唇动作"，不可混用：

          | 类型 | 标签 | 角色嘴巴 | 典型场景 |
          |------|------|---------|---------|
          | 开口台词 | `台词（角色名，开口）：` | **要动** | 角色当场说出的话 |
          | 低语/耳语 | `台词（角色名，低语）：` | **轻微动** | 极轻声、贴耳说、怒火压制下的低吼 |
          | 内心OS | `内心OS（角色名，不开口）：` | **不动** | 内心独白（后期配VO音，嘴不动） |
          | 回忆音 | `回忆音（角色名，不开口）：` | **不动** | 角色脑海中浮现的声音/往事 |
          | 画外声音 | `画外音（不入画，描述声源）：` | 不在画面 | 另一人说话但不入画；叙述者旁白 |

          ❌ 错误示范（让内心独白变成开口台词）：
          `对白（陈稳，画外音）："……好。他要的是口供，不是真相。那我给他一个能活命的口供。"`

          ✅ 正确示范：
          `内心OS（陈稳，不开口）[从慌乱转入冷静计算]："……好。他要的是口供，不是真相。那我给他一个能活命的口供。"`
          （陈稳脸上呈现内心转变的表情，嘴不动，这句话后期做旁白配音）

        - **开口台词的写法**：让模型理解这句话怎么说——情绪、语气、节奏。
          不用固定格式，只要让模型理解即可：内联标注、画面描述里说、标点暗示都行。
          判断标准：如果你完全不了解这部片子，只看这句台词，能猜出角色的情绪和说话方式吗？能→ 可以；不能 → 补信息。

        - 可指定环境音 + 动作音效（如雨声、脚步声、关门声、玻璃碎裂声）
        - **🔴 画外音/Off-Screen 声音的写法（v11.0 新增）**：
          当某个角色的声音在画面外响起（画外音、旁白、OS 对白），处理分两步：

          **第一步（视觉防污染）**：此角色的名字**绝对不能出现在【画面内容】里**。
          视频模型看到任何人名都会把他当成视觉生成对象，哪怕你没传他的参考图，他也会凭文字描述生成出来。
          ❌ "赵克用的话在画外响起，陈稳听完……"（名字泄漏 → 模型生成赵克用）
          ✅ "低沉施压的男声在画外响起，陈稳听完……"（只描述声音特征，不给视觉锚点）

          **第二步（声音内容具体化）**：在声音字段写清楚这个声音说了什么、什么语气。
          ❌ "赵克用的疏磺施压台词"（对模型没意义，它不知道内容）
          ✅ "画外低沉施压男声：'陈稳，账上少了三千斤铁，给本官一个交代。'"

          如需在【参考设定】里建立场景前提（让模型理解画面外的权力关系/情境），用中性描述：
          "这是一场审讯场景，陈稳处于弱势方，画外传来上位者低沉的盘问声。" → 不出现人名，但交代了人物关系和情境。

        - 不要指定背景音乐/插曲/配乐——音乐由音乐总监单独设计，后期剪辑时配上

[群演/一次性配角处理]
    导演讲戏本中可能提到不在 character-prompts.md 中的人物（群演、一次性配角）。处理方式：
    - 不为这些人物分配 @ 引用编号
    - 在提示词中直接用文字描述其外观和动作
    - 外观描述从导演讲戏本的导演阐述中提取（导演已在阐述中具体描述了这些角色的外观）
    - 示例：导演阐述中提到"路人甲侧头对同伴低声说"，讲戏本中描述其为"尖脸眯缝眼的白袍学员"
      → 提示词中写"一个尖脸眯缝眼的白袍学员侧头低声说..."，不使用 @ 引用

    故事板模式下也同样：群演不出现在万能故事板的 M2 角色参考模块（仅画主要角色），但可以在 M4 分镜网格的 Cut 描述中文字提及。

[严禁视频音乐红线]（最重要的硬规则）

    **绝对不要在 Seedance 提示词中描述任何背景音乐、插曲、配乐**——只能写：
    - ✅ 环境音（雨声、风声、人群嘈杂、海浪、街道喧闹等）
    - ✅ 动作音效（脚步、开门、玻璃碎裂、敲击键盘、引擎启动等）
    - ✅ 台词（用引号标注，可注明语气/音色）

    为什么这条是硬红线：
    用户后期会拿音乐总监设计的「原创音乐」或「市面推荐音乐」贴到剪辑好的视频上。
    如果 Seedance 生成的视频自带 BGM，新音乐和老 BGM 就会**双轨冲突**——你听不出来是两层音乐，但观众一听就别扭，整段视频废一遍。
    而环境音、音效、台词不冲突，可以保留，反而能省去剪辑阶段的重新拟音工作。

    如果导演讲戏本里提到了"此处响起 M01 主题曲"——这是**给后期的标记**，不是提示词内容。处理方式：
    - 在视频提示词表的 `音乐编号` 字段写"M01 主题曲（后期配）"
    - 在 Seedance 提示词正文中**绝口不提音乐**
    - 在万能故事板的 M5 底部辅助四件套之声音设计模块可写 M01 编号（这是给观众/导演看的视觉信息，不进 Seedance 视频生成）

    自检：每条提示词写完后，搜索关键词「音乐 / BGM / 配乐 / 主题曲 / 旋律 / 背景音 / 钢琴响起 / 弦乐响起」，如果在提示词正文中找到任何一个，回去改。

[风格提示词放最前]（关键格式规范）

    每条 Seedance 视频提示词的**第一段必须是项目视觉风格描述**，与服化道的人物/场景/道具提示词保持完全一致。

    为什么：
    1. 用户复制提示词时一眼能找到风格段，便于跨集统一
    2. 跨工具切换（Seedance / 可灵 / Runway）时一键改风格
    3. Seedance 把风格关键词放前面比放后面更容易命中

    示例（单镜模式）：
    ```
    [项目视觉风格] 3D CG 写实风，皮克斯质感，柔和暖光，材质细腻，色彩饱和度中等。

    [画面通用描述]
    @图片1（林书白）站在 @图片5（雨夜街角）的路灯下，手中紧握 @图片14（老式怀表）...
    ```

    示例（故事板模式）：
    ```
    [项目视觉风格] 3D CG 写实风，皮克斯质感，柔和暖光，材质细腻，色彩饱和度中等。

    [画面通用描述]
    本 Cut 对应 @P02-storyboard.png 上 Cut 3 这一格的构图：诺娜手指轻触画笔，画笔被她拿起，笔尖金色光晕清晰可见，背景虚化...
    ```

    注意：故事板模式下，提示词第一段写**视频画面的项目视觉风格**（如 3D CG 写实风），不是写故事板大图自身的风格（如 cinematic_realism）。两者解耦：
    - 故事板大图风格 = Nano Banana 生故事板时的风格（5 候选之一）
    - 视频画面风格 = Seedance 生视频时的风格（项目 settings.visual_style）

[衔接机制（双模式都用）]

    详见 references/transition-mechanism.md。简化版：

    四层衔接保障：
    1. 资产一致性（assets/visual/ 跨集复用）—— 现有 ✓
    2. 场景一致性（assets/visual/ 跨集复用）—— 现有 ✓
    3. 风格一致性（settings.visual_style + 故事板风格决策树）—— v7.0 新增 ✓
    4. 运动/情绪衔接（from_previous + to_next 字段 + episode-master 衔接表）—— v7.0 新增 ✓

    分镜师工作流：
    - 读 P(X-1) 最后一镜 + P(X+1) 第一镜（来自导演讲戏本）
    - 写本 P0X 的承接上段 + 引出下段（5 维度信息：位置/道具/光影/环境/情绪）
    - 故事板模式：写在故事板提示词的 YAML 头部（M6 frontmatter）
    - 单镜模式：写在视频提示词表的 `承接` 列

    底线：衔接靠**前期一次性设计 + 描述层面相同**，不是「让 AI 把帧对齐」。

[镜头数与编号规范]

    | 参数 | 规范 |
    |---|---|
    | 默认镜头数 | 5-8 镜（最佳剪辑感） |
    | 上限 | 12 镜（蒙太奇等特殊情况） |
    | 超长处理 | 自动拆为 P0X.A + P0X.B（衔接字段套用） |
    | 编号格式 | Cut 1 / Cut 2 / ... / Cut N |
    | P0X 前缀位置 | YAML 头部元数据 |
    | 每镜最短时长 | min_seconds（来自 .project-config.json，默认 4s）；绝不低于 1.2s |
    | 每镜最长时长 | max_seconds（来自 .project-config.json，默认 15s；**硬约束，不可超**） |
    | 单 P0X 总时长 | 约 max_seconds ± 2 秒（如 max=15s → 约 13-17s；max=30s → 约 28-32s） |

    超 12 镜的拆分示例：
    - 原 P03 = 16 镜 → 拆为 P03.A（8 镜，前 15s） + P03.B（8 镜，后 15s）
    - P03.A 的 from_previous 接 P02 末，to_next 写「接 P03.B（同空间，时间无跳）」
    - P03.B 的 from_previous 写「接 P03.A（同空间，时间无跳）」，to_next 接 P04

[输出 episode-master.md]（v7.0 强制要求）

    所有 P0X 写完后，按 templates/episode-master.template.md 输出 outputs/<集数>/episode-master.md。

    必含 7 段：
    1. 本集基本信息（项目/集数/总时长/剧情点数/模式/故事板风格/视觉总锚）
    2. 全片衔接表（每个 P0X 一行：上段衔接 / 故事板缩略 / 下段衔接 / 风险）
    3. 故事板提示词表（仅故事板模式）
    4. 视频提示词表
    5. 资产清单（assets/visual/ 引用列表）
    6. 音乐编号对应（M01-M0N，关联音乐总监输出）
    7. 用户操作清单（具体步骤）

    跳跃风险标记：
    - ⚠ 时间跳跃 / ⚠ 空间跳跃 / ⚠ 情绪跳跃 / ⚠ 角色跳跃 / ⚠ 道具消失
    - 应对建议见 references/transition-mechanism.md §四

[禁忌规则]
    - 不要使用否定句（AI 不理解否定，可能产生相反效果）
        "不要移动镜头" ✗ → "镜头保持固定" ✓
    - 不要重复导演讲戏本和人物/场景提示词中已有的静态内容描述
        重点描述"变化"：动作、运动、情绪转变
    - 不要在一条提示词中塞入叙事上不相关的场景
        一条提示词 = 一个完整的叙事段落（可含多组镜头，但叙事连续）
    - 不要使用与导演讲戏本和人物/场景提示词矛盾的描述
    - 不要为不在 character-prompts.md / scene-prompts.md / prop-prompts.md 中的人物/场景/道具使用 @ 引用
    - **不要在同场景的连续 Cut 中省略场景参考图**（即使上一 Cut 已经引用过该场景——模型没有记忆，每 Cut 独立，省略 = 凭空生成背景 = 场景不一致；详见 seedance-prompt-methodology.md [场景参考图连续性原则]）
    - **不要在提示词正文中描述任何背景音乐**（详见 [严禁视频音乐红线]）
    - **不要省略衔接 frontmatter 字段**（v7.0 新增 —— from_previous + to_next 是必填）
    - **不要混用模式**（一个剧情点要么故事板模式要么单镜模式，不要混）
    - **不要超 12 镜不拆**（超 12 镜必须拆 P0X.A + P0X.B）

[注意事项]
    - seedance-prompt-methodology.md 是核心方法论（双模式通用），必须遵守
    - 故事板模式必须读 references/universal-storyboard-methodology.md（v7.0 核心新文档）
    - 故事板风格判定必须读 references/storyboard-style-decision-tree.md
    - 衔接机制必须读 references/transition-mechanism.md
    - 4 个万能故事板 example 文件可直接参考各风格写法
    - episode-master.md 是分镜师阶段的强制产物（双模式都要）
    - 跨集时必读上一集 episode-master.md 沿用风格 + 衔接习惯

[底线提醒]
    > 故事板是手段，不是目的。
    >
    > 一切设计都为「让 AI 产出高质量 15s 片段、多片段拼出高质量视频」服务。
    > 如果某个 P0X 用单镜模式更适合（如长镜头抒情、单一画面），分镜师应主动选用单镜模式，**不为了故事板而故事板**。
    >
    > 衔接保障来自：资产复用 + 风格锁定 + 剧情连贯（编剧/导演前期已设计）+ 后期剪辑 + 衔接 frontmatter（前期一次性写完）。
