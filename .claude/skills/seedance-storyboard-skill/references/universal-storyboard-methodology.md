# 万能故事板方法论

> 本方法论吸收 11 个工业级故事板案例的精华提炼而成。所有规则均经实战验证，并锁定「服务出好视频」这一底线（故事板是手段，不是目的）。

## 一、什么是万能故事板

「万能故事板」= 1 个剧情点 P0X 对应 1 张高密度复合 PNG，把该剧情点需要的：

- **所有视觉资产**（角色三视图 / 场景概念图 / 关键道具）
- **所有分镜信息**（Cut 1-N 网格 + 每镜元数据）
- **所有辅助信息**（灯光 / 情绪关键词 / 音频音乐 / 摄影笔记 / 色板）
- **衔接 frontmatter**（承接上段 / 引出下段）

打包到一张 16:9 横版大图里，喂给 Seedance 2.0 时作为**单一素材引用**（替代分散的多张 PNG）。

### 1.1 为什么要做万能故事板

1. **视觉一致性最强**：综合包装后，Seedance 一次看到所有资产，跨 Cut 一致性远好于多图拼接
2. **节奏剪辑感天然**：Cut 1-N 一镜一格，让 15s 视频天然有多镜头剪辑感
3. **导演沟通工具**：即使不用 Seedance，也是好东西
4. **简化视频提示词**：每 Cut 只引用 1 张 PNG，不用对齐多个 @图片

### 1.2 与单镜模式的关系（双轨）

| 维度 | 故事板模式 | 单镜模式 |
|---|---|---|
| 视频提示词每 Cut 素材 | 1 张 P0X-storyboard.png | character/scene/prop 多张 |
| 视觉一致性 | 综合包装最强 | 多图各自参考 |
| 剪辑感 | Cut 1-N 一镜一格 | 单镜一镜头 |
| 适用 | 多镜蒙太奇/节奏密集/群戏 | 单一画面/长镜/抒情 |
| 制作成本 | 多 1 步：生 P0X-storyboard.png | 直接生视频 |

**底线**：两种模式都不丢「assets/visual/ 是源头」原则——故事板的资产模块通过提示词引用 assets/visual/ 已生成的 PNG，不重新设计。

## 二、6 必备模块（缺一不可）

### M1 顶部元数据栏（frontmatter 横条）

**位置**：故事板大图最顶部一条横栏（高度约占 8-10%）。

**必填字段**：

| 字段 | 内容 | 示例 |
|---|---|---|
| 标题 | 项目名 + 副标题 | 《错过之后，学会放手》短片分镜 |
| 剧情点 ID | P0X | P01 |
| 镜头数 | Cut 总数 | 6 镜（Cut 1 至 Cut 6） |
| 总时长 | 约 15s | 约 15 秒 |
| 影片类型 | 题材关键词 | 都市情感 / 剧情短片 |
| 主色调 | 5 个色块（横向并列）| 深蓝 / 雨夜黑 / 霓虹红 / 路灯暖黄 / 湿地反光灰 |
| 风格关键词 | 3-6 个词 | 写实电影感 / 现实主义 / 情感张力 |
| 拍摄地点 | 简短描述 | 现代城市商业街区 / 户外 |

**写法**：在故事板提示词中，要求 Nano Banana 生成时把这条横栏放在画面顶部，文字水平排列、字号清晰可读。

### M2 角色与造型参考

**位置**：左侧或左上区域，约占画面 1/4 - 1/3。

**必填内容**：每个主要角色一组：

- **三视图**：正面全身 / 侧面全身 / 背面全身（衣装一致）
- **面部特写**：1 张近景头像
- **表情包**：4-6 个不同情绪表情小图（按本剧情点需要）
- **服装/配饰描述**：文字标注「外套：牛仔；鞋：黑靴；配饰：耳环、项链」

**多角色处理**：男主一组放上、女主一组放下；或主角一组、配角一组。

**写法示例**（提示词片段）：

```
左上区域：角色与造型参考
- 男主「阿杰」（@图片1，参考 character-aiyu.png）
  · 三视图：正面/侧面/背面全身
  · 面部特写一张
  · 表情包：期待 / 失落 / 心碎 / 决绝 / 释怀 / 重生
  · 造型：牛仔外套 + 灰衬衫 + 黑裤；配饰耳环、项链
- 女主「小敏」（@图片2，参考 character-xiaomin.png）
  · 同上结构
  · 造型：白衬衫 + 牛仔裤；配饰耳环、项链
```

### M3 场景设计与动线规划

**位置**：左中或中下区域，约占画面 1/4。

**必填内容**：

1. **场景透视图**：1 张该剧情点主场景的概念图（街角 / 客厅 / 山谷祭坛等）
2. **俯视平面图**：1 张鸟瞰图，标出主要家具/障碍物布局
3. **机位编号**：用 C1 / C2 / ... 或 A / B / C / D 标注每个 Cut 的拍摄机位
4. **角色起止位置**：用「人物图标」标记角色起点与终点
5. **路径线**：红色虚线表示角色移动路径
6. **镜头方向箭头**：每个机位标出镜头朝向（蓝色箭头）

**写法示例**：

```
左中区域：场景设计与动线规划
- 场景透视图：现代城市雨夜街角，地铁口、斑马线、路灯、玻璃橱窗反光、湿润柏油路
- 俯视平面图：标出 COFFEE 店、地铁入口 A1、斑马线、红绿灯、路灯位置
- 机位编号 C1-C6 对应 Cut 1-6
  · C1：街对面广角机位，拍男主等待
  · C2：斑马线侧面机位，拍两人对视
  · C3：低机位拍递伞特写
  · C4：近景双人对面机位
  · C5：男主背后跟拍机位
  · C6：广场上方俯拍机位
- 路径线：女主从对面走来 → 走到男主前 → 转身离开（红色虚线）
- 镜头方向：每个机位画蓝色箭头表示拍摄朝向
```

### M4 分镜脚本网格

**位置**：右侧或中间，占画面最大区域（约 50%）。

**必填内容**：

- **Cut 1 至 Cut N 网格**（默认 5-8 镜，上限 12 镜，超 12 拆为 P01.A + P01.B）
- **网格布局**：2x4（8 镜）/ 4x4（16 镜）/ 5x1 横列（5 镜）/ 3x3（9 镜）等
- **每镜单元包含**：

| 字段 | 必填 | 示例 |
|---|---|---|
| 序号 | ✓ | Cut 1 / Cut 2 / ... |
| 缩略画面 | ✓ | 该镜的核心画面（一张小图） |
| 时长 | ✓ | 1.2s / 1.8s / 2.5s（精确到 0.1 秒） |
| 焦距 | 可选 | 24mm / 35mm / 70-100mm |
| 景别 | ✓ | 全景 / 中景 / 近景 / 特写 / 超广角 / 低机位 |
| 运动方式 | ✓ | 静态 / 缓慢推进 / 后拉 / 跟拍 / 环绕 / 低机位滑动 |
| 描述 | ✓ | 主体动作 + 表情 + 情绪（≤30 字） |
| 对白气泡 | 可选 | 「绝对不行」（绿色或白色气泡画在画面上） |

**关键约束**：
- 每镜 ≥ 1.2 秒（< 1.2s 在 Seedance 输出会被压缩成跳帧）
- 总时长 = Σ(每镜时长) ≈ 15 秒 ± 2 秒
- 🔴 **Cut 缩略图镜头框按 settings.aspect_ratio 画**（v7.0.2）：
  - 项目 9:16 → 每个 Cut 缩略图是**竖向矩形**（即使故事板大图本身是 16:9 横版，每个 Cut 也是竖矩形小图）
  - 项目 16:9 → 每个 Cut 缩略图是横向矩形
  - 项目 1:1 → 每个 Cut 缩略图是方形
  - 项目 21:9 → 每个 Cut 缩略图是超宽矩形
  - 在故事板提示词的 M4 段必须明确写：「**Cut 缩略图按 <aspect_ratio> 画**，反映最终视频画幅，不要画成 16:9（这是故事板本身的画幅，不是 Cut 的）」
  - 为什么：Cut 缩略图是给用户/Seedance 看的"最终视频构图预演"，必须按真实视频比例呈现

### M5 底部辅助四件套

**位置**：故事板大图最底部一条横栏（约占画面 15%）。

**必填四件套**（横向并列）：

1. **灯光/氛围参考小图组**（4-6 张小图）：
   - 不同时段/情境的光线参考（如「白天冲突前」「冲突时刻」「失去时刻」「重生时刻」）
   - 文字标注每张小图的时刻

2. **情绪关键词**（emoji + 文字）：
   - 用 emoji + 关键词组合（如 ❤️ 期待 / 💔 失落 / 😔 孤独 / 💪 决绝 / 🌅 释怀）
   - 按情绪节奏排列（轻松→紧张→低沉→释怀→激昂）

3. **声音与音乐设计**（图标 + 文字）：
   - 环境音：城市街道人声、车流、脚步声
   - 音乐风格：钢琴 + 弦乐 / 情感渐进 / 动态变化（**注意：M01 / M02 编号写在这里，但 Seedance 视频提示词正文绝口不提音乐**）
   - 整体氛围：真实自然、情感流淌、留有余韵

4. **摄影与影像风格笔记**（相机图标 + 文字）：
   - 镜头语言：多用跟拍、推近、特写
   - 镜头类型：广角 + 中景，50mm 中景为主，85mm 特写情绪
   - 色彩质感：冷暖对比，突出情绪转折
   - 画面质感：电影级清晰度、轻微颗粒、增强现实感
   - 后期处理：情绪分级调色、柔和暖光、增强生活感

### M6 衔接 frontmatter（YAML 头）

**位置**：故事板提示词文档的 YAML 头部（不在画面里，是提示词文本的头部）。

**必填字段**：

```yaml
---
剧情点 ID: P01
故事板 ID: P01-storyboard
时长: 约 15 秒
镜头数: 6（Cut 1 至 Cut 6）

承接上段:
  上段 ID: P00（首段填「无」）
  上段最后一镜简述: 小敏转身向左走，背影消失在街角
  本段第一镜衔接策略: 接续小敏走在湿润街道远景，方向左前，雨势相同

引出下段:
  下段 ID: P02
  本段最后一镜简述: 黑伞独自留在路灯下
  下段第一镜衔接策略: 镜头从黑伞拉远到全景街道，时间略过 5 分钟

风格: cinematic_realism
模块组合: [M1, M2, M3, M4, M5, M6, O1]
---
```

**写作要求**：
- `承接上段` 的内容来自**上一个 P0X 的最后一镜描述**（从导演讲戏本提取）
- `引出下段` 的内容指向**下一个 P0X 的第一镜衔接策略**（前期一次性设计）
- 首段 `承接上段` 填「无（开场）」，末段 `引出下段` 填「无（结尾）」

## 三、4 可选模块（AI 按场景选）

### O1 场景状态图组（多张俯视图）

**触发条件**：单场景内主体位置随剧情大幅变化（如「等待 → 对峙 → 离开」3 阶段）。

**典型布局**：右上侧 3 张小俯视图，并列排版：
- 状态 1：初始布局（主体起始位置）
- 状态 2：中段状态（对峙 / 协作 / 清洁中）
- 状态 3：收束/爆发状态（终态）

**每张小俯视图**包含：
- 场景关键家具/障碍物
- 主体位置（人物图标 / 产品图标）
- 移动方向（小箭头）
- 视线方向（虚线）

### O2 关键道具特写模块

**触发条件**：该剧情点有「推动剧情的关键道具」（道具复现 ≥ 2 次或承担情节作用）。

**典型布局**：右侧或左下专门一格，约占画面 10%。

**内容**：
- 道具整体形态（1 张主图）
- 道具细节特写（2-4 张小图，如剑柄/剑刃/纹路/能量效果）
- 道具用途说明（1-2 行文字）

**示例题材**：
- 仙侠：断剑 / 法杖 / 灵兽
- 都市情感：黑伞 + 信封 / 戒指 / 老式怀表
- 动画：发光气球 + 星光粒子 / 魔法画笔
- 战争奇幻：法杖 / 战车 / 金色法阵

### O3 对白气泡（直接画在分镜上）

**触发条件**：该剧情点有重要对白（≥ 2 句台词）。

**写法**：在 M4 分镜网格的对应镜头小图上，画对白气泡（绿色 / 白色 / 连环画式），写出台词。

**示例**：
- Cut 2：男主特写 + 绿色气泡「等下来吃面可以吗？」
- Cut 3：女主特写 + 白色气泡「绝对不行」
- Cut 4：男主特写 + 红色气泡「哎呀，别这样」

**注意**：对白只在故事板大图里画给观众看；视频提示词中通过「对白」字段单独写入。

### O4 十六进制色板

**触发条件**：商业广告 / 高端设定项目（电商、品牌、概念美术）。

**位置**：底部辅助区与色板区合并，列出十六进制色值。

**示例**：

```
色板与风格说明
- 暖白 #F7F6F3
- 浅灰 #E6E7EA
- 木色 #D9B98C
- 清爽蓝 #5FA8F3
- 清洁感白光 #FFFFFF
- 柔和家居暖光 #FFF1D6
```

**用途**：让 Nano Banana 生成时严格锚定项目色彩，避免色调漂移。

## 四、模块组合决策

```
基础 = M1 + M2 + M3 + M4 + M5 + M6（必备 6）

if 单场景且角色 ≥ 2 且位置随剧情大幅变化:
    + O1（场景状态图组）

if 该剧情点有「推动剧情的关键道具」:
    + O2（关键道具特写）

if 该剧情点有 ≥ 2 句重要对白:
    + O3（对白气泡）

if 项目类型 in [电商, 品牌广告, 概念美术]:
    + O4（十六进制色板）
```

**模块清单输出**：在故事板提示词的 YAML 头部 `模块组合: [M1, M2, M3, M4, M5, M6, O1, O3]` 列明本次启用的模块。

## 五、提示词写作铁律（基于 11 案例提炼）

### 5.1 必有「核心目标段」

每张故事板提示词的开头，必须明确告知 Nano Banana 这张图的用途。

**两种典型表述**：

```
【核心目标】
这张图是核心故事板，用于后续裁 Cut 上传 Seedance 逐镜头生成视频。
重点是讲清楚一场戏：[XXX 剧情概要]。
```

或

```
【核心目标】
这张图不是故事板，而是 [XXX 资产/产品/角色] 一致性参考板。
用于后续 Seedance 视频生成时保持 [XXX] 一致。
```

### 5.2 必有「画面结构段」

明确告知 Nano Banana 启用了哪些模块、各模块在画面中的位置。

**示例**：

```
【画面结构】
整体为专业影视分镜故事板，深色背景，清晰网格排版。
- 顶部：标题栏 + 元数据（M1）
- 左上：角色与造型参考（M2，男女主各一组）
- 左中：场景设计与动线规划（M3）
- 右侧：8 镜分镜网格（M4，2x4 布局）
- 右上：3 张场景状态图（O1）
- 底部：灯光参考 + 情绪关键词 + 音频设计 + 摄影笔记四件套（M5）
- 整体画幅 16:9 横版（故事板复合图本身的画幅，为信息密度最大化；不同于 settings.aspect_ratio）
```

### 5.3 必有「限制段」（负向提示）

11 个案例都有这一段。**v7.0 必须强制要求**。

**典型限制**：

```
【限制】
- 所有分镜必须发生在同一个 [XXX] 场景
- 人物服装、发型、脸型保持一致
- 不要生成古装（如本片是现代题材）
- 不要生成校园（如本片不在校园）
- 不要生成婚礼、医院、机场等无关场景
- 不要生成吵架大哭的狗血场面
- 不要生成杂乱拼贴
- 必须像正式影视分镜板，方便裁出 Cut 1 到 Cut N 用于 Seedance
```

### 5.4 风格段简短 ≤ 30 字 + 节奏关键词三段式

故事板自身的风格描述要**短**。节奏关键词三段式表达情绪推进。

**示例**：
- 都市情感：`写实电影感 / 节奏：等待-错过-释怀`
- 仙侠：`史诗写实 / 节奏：压制-反击-终决`
- 喜剧：`黑白线稿漫画风 / 节奏：紧张-荒诞-反转`
- 商业：`商业干净风 / 节奏：痛点-解决-焕新`

### 5.5 角色描述五维度齐全

即使提供了 @ 引用，文字也要写五维度摘要（防 Nano Banana 漏看图）：

1. **身材**：身高、体型、年龄段
2. **面相**：五官特征、肤色、发型
3. **表情**：基础表情风格 + 本剧情点的关键表情
4. **服装**：上衣 / 下装 / 鞋 / 配饰
5. **动作风格**：体态特点、走路方式、惯性姿势

### 5.6 故事板大图默认 16:9 横版（与最终视频画幅解耦）

**这是 11 案例的硬规律**：

- 故事板大图：默认 16:9 横版（信息密度最大化；这是复合图本身的画幅，不是视频的）
- 最终视频画幅：按 `settings.aspect_ratio`（10 候选之一：1:1 / 2:3 / 3:2 / 3:4 / 4:3 / 9:16 / 16:9 / 9:21 / 21:9 / Auto）在每个 Cut 内呈现
- 在分镜网格的每个 Cut 缩略图里，按视频的实际画幅画镜头框（即如 settings.aspect_ratio = 9:16，则每个 Cut 缩略图是竖向矩形）

### 5.7 氛围段允许「等号对比」

11 案例中的高级写法：用 `角色 A=情绪 1 / 角色 B=情绪 2` 明确双方情绪关系。

**示例**：
- `阿杰=主导(递伞) / 小敏=拒绝(克制)`
- `灰袍法师=神圣孤独 / 黑甲军团=压迫推进`
- `露娜=焦急 / 诺亚=温暖支援`

### 5.8 商业项目必填十六进制色板

如启用 O4 模块，色板**必须列十六进制**（不是色名描述）：
- ✗ 「暖白、浅灰、木色」（色名易漂移）
- ✓ 「#F7F6F3 / #E6E7EA / #D9B98C」（精确锚定）

## 六、提示词整体结构

### 6.1 推荐顺序

```
1. YAML 头部（M6 衔接 frontmatter + 风格 + 模块组合）

2. 【核心目标】 段（5.1）

3. 【整体风格】 段（短描述 + 节奏关键词三段式 5.4）

4. 【画面结构】 段（列出启用模块 + 位置 5.2）

5. 各模块详细描述：
   M1. 顶部元数据栏：[展开]
   M2. 角色与造型参考：[展开，含五维度 5.5]
   M3. 场景设计与动线规划：[展开]
   M4. 分镜脚本网格：[展开 Cut 1-N，每镜 8 个字段]
   M5. 底部辅助四件套：[展开]
   O1/O2/O3/O4（如启用）

6. 【限制】 段（5.3 负向提示）

7. 【画幅与排版】 段：「整体画幅 16:9 横版，专业故事板风格...」
```

### 6.2 长度参考

- **完整版**（必备 6 + 多个可选）：800-1500 字
- **精简版**（必备 6 + 0 个可选）：500-800 字
- **超长警戒**：> 1800 字时优先砍 M3 详细度（保留 M1/M2/M4），避免 Nano Banana token 上限溢出

## 七、与 assets/visual/ 的对接（@ 引用机制）

### 7.1 资产源头不变

`assets/visual/` 依然是源头：
- `character-prompts.md` → 用户生 character-X.png
- `scene-prompts.md` → 用户生 scene-X.png
- `prop-prompts.md` → 用户生 prop-X.png

### 7.2 故事板提示词如何引用 assets/visual/

万能故事板提示词中，在描述 M2 / M3 / O2 模块时，**通过 @ 引用语法**告知 Nano Banana 使用已有 PNG 作为输入参考：

```
M2. 角色与造型参考
- 男主「阿杰」（参考 @图片1：assets/visual/characters/character-aiyu.png）
  请基于 @图片1 的人物形象，绘制三视图（正/侧/背）+ 面部特写 + 6 张表情包
- 女主「小敏」（参考 @图片2：assets/visual/characters/character-xiaomin.png）
  请基于 @图片2 的人物形象，绘制三视图 + 面部特写 + 6 张表情包

M3. 场景设计与动线规划
- 主场景：现代城市雨夜街角（参考 @图片3：assets/visual/scenes/scene-rainy-street.png）
  请基于 @图片3 的场景气质，绘制场景透视图 + 俯视平面图

O2. 关键道具特写
- 黑伞（参考 @图片4：assets/visual/props/prop-black-umbrella.png）
- 信封（参考 @图片5：assets/visual/props/prop-letter.png）
```

**核心机制**：让 Nano Banana 「看到」已有 PNG，确保万能故事板里的角色/场景/道具与 assets/visual/ **视觉一致**。

### 7.3 单条提示词的 @ 图片限制

Nano Banana 最多支持 **9 张 @ 图片输入**。万能故事板的实战配置：

- 主要角色 2-3 个 → 2-3 张 @ 图片
- 主场景 1-2 个 → 1-2 张 @ 图片
- 关键道具 0-3 个 → 0-3 张 @ 图片
- 总计：3-8 张，留 1-2 张余量

如果实际超 9 张：先砍道具（用文字描述代替）→ 再砍次要场景 → 留主要角色 + 主场景。

### 7.4 群演 / 一次性配角

不在 `character-prompts.md` 中的群演，**不分配 @ 引用**，在提示词里直接用文字描述（沿用原 seedance-prompt-methodology.md 的群演规则）。

## 八、失败诊断 / 自检 checklist

### 8.1 写完故事板提示词后的自检清单

- [ ] M1 顶部元数据栏的 8 个字段齐全
- [ ] M2 每个主要角色的三视图 + 面部特写 + 4-6 表情包齐全
- [ ] M3 含场景透视图 + 俯视平面图 + 机位编号 + 路径线 + 镜头方向箭头
- [ ] M4 Cut 数在 5-12 之间，每镜 8 字段（序号/时长/焦距/景别/运动/描述/对白/缩略画面）齐全
- [ ] M4 总时长 ≈ 15s ± 2s，每镜 ≥ 1.2s
- [ ] M5 底部四件套都有（灯光/情绪/音频/摄影）
- [ ] M6 YAML 头部 from_previous + to_next 字段填写完整
- [ ] 启用的可选模块（O1/O2/O3/O4）各自规范
- [ ] 【核心目标】段已写
- [ ] 【画面结构】段已写
- [ ] 【限制】段（≥ 5 条负向提示）已写
- [ ] 风格描述 ≤ 30 字 + 节奏关键词三段式
- [ ] 角色描述五维度齐全
- [ ] 商业项目色板列十六进制
- [ ] @ 引用 ≤ 9 张
- [ ] 提示词总长度 < 1800 字
- [ ] 整体画幅强调 16:9 横版

### 8.2 用户生 PNG 失败时的诊断

| 现象 | 可能原因 | 修复方法 |
|---|---|---|
| 角色形象与 assets/visual/ 不一致 | @ 引用没起作用 / 描述与 PNG 矛盾 | 检查 @ 引用 + 五维度描述与 PNG 一致 |
| 分镜网格少于 N 镜 | 提示词中 Cut 数列举不清 | 在 M4 段每个 Cut 单独列项，明确 Cut 1 至 Cut N |
| 风格漂移（如要写实生成卡通） | 风格段太短 / 限制段缺位 | 风格段 + 限制段「不要卡通、不要二次元」并存 |
| 画面拼贴感重 / 模块混乱 | 画面结构段没写清模块位置 | 在 M2 中明确每模块位置（左上/中/右等） |
| 文字模糊 / 标签乱码 | 元数据字段太多 | 砍 M1 字段到 5-6 个核心 |
| 角色脸跑偏 | character PNG 没作为 @ 引用输入 | 强制使用 @ 引用 + 五维度描述并行 |
| 故事板被画成纵版 | 画幅强调不够 | 在【画幅与排版】段强调 16:9 横版 |
| Nano Banana 拒绝生成（内容审查） | 限制段或描述触红线 | 检查是否描述了过暴力/性暗示/真实人脸 |

### 8.3 整张图返工的判定

**直接重生（不返工）的指标**：
- 缺少 ≥ 2 个必备模块
- 角色形象与 assets/visual/ 严重不符
- 故事板复合图被生成成纵版（不是预期的 16:9 横版；与 settings.aspect_ratio 无关，复合图本身必须 16:9）
- Cut 数严重不符（如要 8 镜实际 3 镜）

**局部修补（返工）的指标**：
- 仅 1 个模块缺失或模糊
- 仅 1-2 个 Cut 不准
- 风格略有偏移但整体可用

## 十、底线提醒

> **故事板是手段，不是目的。**
>
> 一切设计都为「让 AI 产出高质量 15s 片段、多片段拼出高质量视频」服务。
> 如果某个 P0X 用单镜模式更适合（如长镜头抒情、单一画面），分镜师应主动选用单镜模式，**不为了故事板而故事板**。
>
> 衔接保障来自：
> 1. **资产复用**（assets/visual/ 跨集一致）
> 2. **风格锁定**（settings.visual_style + 故事板风格决策树）
> 3. **剧情连贯**（编剧/导演前期已设计）
> 4. **后期剪辑**（用户用剪辑工具串接 Cut 1...Cut M）
> 5. **衔接 frontmatter**（M6 from_previous + to_next，前期一次性写完）
