# 用户消息话术库（User-Facing Messages）

> 这个文件集中存放制片人 KAIKAI 在与用户交互时使用的**所有标准话术模板**。
>
> **拆分逻辑**：CLAUDE.md 关注"AI 怎么干活"（流程/调度/审核/规则），本文件关注"AI 对用户说什么话"。两者解耦后：
> - 调话术不动主控逻辑
> - 迭代主控逻辑不会误改用户体验
> - 用户体验/语气/中英文版可以集中演进
>
> **使用方式**：CLAUDE.md 在需要发送用户消息的位置用 `见 user-messages.md > <锚点>` 引用本文件对应段。
>
> **格式约定**：每段以 `## <锚点>` 起头，下方代码块内是要发给用户的实际文案。文案中 `{变量}` 表示运行时替换。

## 路径 B 启动补设定（五问）

发送时机：检测到 `input/剧本/` 有文件 + `assets/story/script-settings.md` 缺失时，**调用导演前**逐题问。

v7.0 起新增第 4 问视觉风格（下游服化道 / 分镜师 / 故事板风格决策树都依赖）。
v7.0.2 起新增第 5 问视觉画幅（决定最终视频比例 + 故事板里 Cut 缩略图镜头框；下游服化道 / 分镜师 / 视频生成都依赖）。

- 目标平台（多选可）：抖音 / 快手 / 小红书 / 视频号 / B站 / YouTube / TikTok / 院线影展

### 第 3 问：对标爆款（v6 新增）

```
🎯 **本项目有没有想对标的爆款？**（决定全流程的"气质参照系"）

请从以下三种回答里挑一种：

**A. 我有对标**（推荐）
请提供 1-5 个：账号名 / 视频标题 / 作品名 / 链接均可（混合也行）。
例：「@张同学 / 《年会不能停》/ B站某 UP 主『某某』2024 年的某条视频」
我会把这些写入项目设定，所有 agent 在产出和审核时都会参考它们的"气质"——不是抄，是知道往哪个方向走。

**B. 我没有但想要推荐**
我会基于你的题材 + 目标平台 + 受众画像，推荐 3-5 个相似的爆款让你认领最像的 1-3 个。

**C. 我不要对标**（"我就要原创 / 不想被框住"）
所有 agent 进入「通用爆款逻辑」模式——按平台规律对照表的通用规则评分，不再做"对标气质"加分项。

输入 **A**、**B** 或 **C**，或直接回答你的对标作品。
```

### 第 5 问：视觉画幅（v7.0.2 新增）

```
📐 **本项目最终视频用什么画幅？**（决定最终视频比例 + 故事板每个 Cut 缩略图的镜头框）

视觉画幅会直接写入 `script-settings.md.aspect_ratio`，分镜师每个 Cut 的镜头框按这个画。
故事板大图（复合图）本身始终用 16:9 横版（信息密度最大化），但**最终视频**按你选的画幅生成。

请基于你的目标平台「{平台}」选 A / B / C：

**A. 我已经有偏好**
   直接告诉我（10 个候选：1:1 / 2:3 / 3:2 / 3:4 / 4:3 / 9:16 / 16:9 / 9:21 / 21:9 / Auto）

**B. 用平台推荐（默认推荐，回车直接用）**
   - 抖音 / 快手 / 小红书 / 视频号 / TikTok → **9:16 竖版**
   - B站（横版投稿）/ YouTube TV / 院线 / 影展 → **16:9 横版**
   - 朋友圈 / Instagram 方版 → **1:1 方版**
   - 电影院线（宽银幕）→ **21:9 超宽版**
   - 短剧（漫剧风格 + 多平台分发）→ **9:16 + 备份 16:9 双轨**（视频先按 9:16 生成，后期可切 16:9）

**C. 让 AI 自决**
   AI 按 [B 推荐] 自动定 → 写入 settings → 后续可以 ~settings 改

输入 **A**、**B**（或回车默认 B）、**C**，或直接告诉我画幅（如 "9:16"）。
```

## 迷路救援协议

发送时机：用户用日常话求助、忘了下一步、用了非 `~` 自然语言时。

```
🆘 别担心，让我帮你定位一下：

**📊 你的项目当前状态**：
{自动运行 ~status 的内部逻辑，输出简要进度表 + 当前所在阶段}

**➡️ 下一步建议**：
{基于当前进度，给出 1-2 条最相关的指令建议，含完整指令格式}

例如：
> 你刚完成 ep01 的服化道，建议接下来：
> - 输入 `~music` 进入音乐设计（推荐）
> - 或输入 `~skip music` 跳过音乐直接进分镜

**📖 完整指令清单**（如果你想全览）：
{自动展开 ~help 的内容}

如果以上都不是你想问的，请直接告诉我你想做什么，我帮你找到对应指令。
```

> 救援后行为约束：
> - 不要假装用户给了 `~status` 或 `~help` 指令——明确说"我检测到你可能需要导航，所以主动帮你看了一下"
> - "下一步建议"必须基于真实项目状态（不能凭空乱推荐）
> - 项目完全为空 → 改用「项目状态检测：空项目欢迎」段
> - 底线：宁可"多救一次"，也不要让用户真迷路时没人接住
