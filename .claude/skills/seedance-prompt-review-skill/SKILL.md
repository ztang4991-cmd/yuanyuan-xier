# Seedance 2.0 提示词审核技能（v7.0 双轨模式）

[技能说明]
    审核分镜师在阶段五的双轨提示词产出。这是项目最后一道质控——通过后用户直接拿去 Nano Banana / Seedance 跑视频。审核越严，废片越少。

[审核对象]
    根据双轨模式不同，审核对象不同：

    **故事板模式**：
    - `outputs/<集数>/storyboards/P0X-storyboard-prompt.md`（每个 P0X 一份故事板提示词）
    - `outputs/<集数>/video-prompts.md`（视频提示词表，单图引用）
    - `outputs/<集数>/episode-master.md`（全片总览 + 衔接表）

    **单镜模式**：
    - `outputs/<集数>/video-prompts.md`（视频提示词表，多图引用）
    - `outputs/<集数>/episode-master.md`（全片总览 + 衔接表）

    （历史项目可能仍叫 `02-seedance-prompts.md`，兼容审核）

[审核流程]
    完整流程框架（5 步：建立理解 → 逐项比对 → 脑内预演 → 评分 → 输出）见
    **`.claude/skills/_shared/review-methodology.md`**

    本 skill 的特殊操作：

    第一步（建立整体理解）的额外材料：
    - 导演讲戏本 `outputs/<集数>/01-director-analysis.md`（核心参照系）
    - 人物提示词 `assets/visual/character-prompts.md`、场景提示词 `assets/visual/scene-prompts.md`、关键道具提示词 `assets/visual/prop-prompts.md`
    - 音乐设计方案 `assets/music/music-design.md`（核对 M01/M02 嵌入是否在元数据字段而非正文）
    - 项目设置 `script-settings.md`（核对 settings.visual_style / aspect_ratio / language / 对标爆款）
    - **如本集是续集**：上一集的 `episode-master.md`（核对故事板风格 + 衔接习惯一致性）
    - 万能故事板方法论 `references/universal-storyboard-methodology.md`（故事板模式审核必读）
    - 风格决策树 `references/storyboard-style-decision-tree.md`（故事板模式审核必读）
    - 衔接机制 `references/transition-mechanism.md`（双模式都必读）

    第二步（模式判定先行）：
    - 先确认本集是「故事板模式」还是「单镜模式」（看分镜师【模式选择】段）
    - 故事板模式 → 按 [故事板模式验收清单] 审
    - 单镜模式 → 按 [单镜模式验收清单] 审
    - 双模式都要审 [episode-master.md 验收清单]

    第三步（脑内预演）的视角：
    - 故事板模式：想象 Nano Banana 拿到提示词 + @ 引用 PNG 后生成的故事板大图长什么样；再想象 Seedance 拿到 @P0X-storyboard.png 后生成的 15s 视频
    - 单镜模式：想象 Seedance 拿到多图 + 描述后生成的视频
    - 是否有描述方式可能导致 Nano Banana / Seedance 理解错误？
    - @ 引用的参考图加上动态描述，生成效果是否会自然？

    [风格提示词位置硬检查]（双模式都先做）
    - 每条 Seedance 视频提示词的**第一段必须是项目视觉风格描述**（如「3D CG 写实风，皮克斯质感」），与服化道的人物/场景/道具提示词风格段一致。
    - 如风格段缺失或不在第一段位置，**该条整体扣 1 分**。
    - 跨集风格一致性：本集风格段是否与前集（character-prompts.md ep01 的风格段）保持完全一致？不一致直接 FAIL。

[故事板模式验收清单]（v7.0 新增）

    [万能故事板提示词审核]（每张故事板 1-10 评分）

        [必备 6 模块齐全性]（一票否决，缺任意 1 个直接 FAIL）

            🔴 M1 顶部元数据栏：标题 / P0X ID / 镜头数 / 总时长 / 影片类型 / 主色调 5 色块 / 风格关键词 / 拍摄地点 — 8 字段必须全在
            🔴 M2 角色与造型参考：每个主要角色的三视图 + 面部特写 + 4-6 表情包 + 五维度文字描述（身材/面相/表情/服装/动作风格）
            🔴 M3 场景设计与动线规划：场景透视图 + 俯视平面图 + 机位编号（C1-CN）+ 角色起止位置 + 路径线 + 镜头方向箭头
            🔴 M4 分镜脚本网格：5-12 镜，每镜 8 字段（序号 / 缩略画面 / 时长 / 焦距 / 景别 / 运动 / 描述 / 对白）
            🔴 M5 底部辅助四件套：灯光参考小图组 + 情绪关键词 + 声音音乐设计 + 摄影笔记
            🔴 M6 衔接 frontmatter：YAML 头部 from_previous（3 子字段）+ to_next（3 子字段）

            缺任 1 模块 → FAIL

        [可选 4 模块合理性]（不评分，但缺漏要点名）

            O1 场景状态图组：单场景内位置变化大时（≥ 2 阶段）应启用
            O2 关键道具特写：道具复现 ≥ 2 次或推动剧情时应启用
            O3 对白气泡：本剧情点有 ≥ 2 句对白时应启用
            O4 十六进制色板：商业广告/电商/品牌广告类项目应启用

            如该启用未启用，在问题摘要点名「O<N> 模块未启用，但本剧情点 <理由> 应启用」

        [写作铁律]（每条 1-10 评分）

            核心目标段：是否明确告知 Nano Banana 这张图的用途（故事板 / 资产板）？
            画面结构段：是否明确启用模块及位置？
            限制段（负向提示）：是否有 ≥ 5 条「不要 XXX」？11 案例都有这一段，必须强制要求。
            风格段简短：≤ 30 字 + 节奏关键词三段式？
            角色五维度齐全：身材/面相/表情/服装/动作风格？
            画幅强调：是否明确写「故事板大图本身 16:9 横版（信息密度），最终视频画幅按 settings.aspect_ratio」？（v7.0.2：两者解耦）
            商业项目色板：是否列十六进制色值（不是色名）？
            提示词总长度：< 1800 字？超长砍 M3？

        [风格判定准确性]（一票否决）

            🔴 故事板风格在 5 候选之一（cinematic_realism / disney_3d_animation / epic_realism / commercial_clean / black_white_manga_lineart）
            🔴 跨集风格统一（首集判定 → 后续集沿用）
            🔴 AI 主动告知用户「【故事板风格判定】」段已写

            违反任 1 条 → FAIL

        [衔接 frontmatter 审核]（一票否决）

            🔴 from_previous 3 子字段全在（上段 ID / 上段最后一镜简述 / 本段第一镜衔接策略）
            🔴 to_next 3 子字段全在（下段 ID / 本段最后一镜简述 / 下段第一镜衔接策略）
            🔴 上段最后一镜简述含 5 维度信息（位置 / 道具 / 光影 / 环境 / 情绪）
            🔴 首段标注「无（开场）」，末段标注「无（结尾）」

            违反任 1 条 → FAIL

    [视频提示词审核 - 故事板模式]（每条 1-10 评分）

        [画幅锁定合规性]（一票否决 · v7.0.2 防传染机制）

            🔴 video-prompts.md / episode-master.md §四 上方有「画幅锁定声明」段，明确写「本集所有 Cut 画幅 = settings.aspect_ratio = <实际值>」
            🔴 每条 Cut 的「描述」列**开头**有画幅指令（如 `[9:16 竖版构图]`、`[21:9 超宽银幕构图]`），与 settings.aspect_ratio 一致
            🔴 用户操作清单 §7 明确说「在 Seedance 工具里手动选 settings.aspect_ratio」（不要让用户用 Seedance 默认）

            为什么强查：故事板复合图永远 16:9，Seedance 看到 16:9 参考图会"传染"输出 16:9 视频；如项目实际是 9:16/1:1/21:9 则视频废
            违反任 1 条 → FAIL

        [素材引用合规性]（一票否决）

            🔴 每个 Cut 的素材引用列**仅 1 张** @P0X-storyboard.png
            🔴 不再引用 character/scene/prop 的散图（应通过故事板综合包装）
            🔴 提示词正文写「本 Cut 对应故事板上 Cut <N> 这一格的构图...」

            如发现混用（既引用故事板又引用散图）→ FAIL

        [Cut 编号规范]（一票否决）

            🔴 编号格式：Cut 1 / Cut 2 / ... / Cut N（不用 P<X>.1）
            🔴 默认 5-8 镜，上限 12 镜
            🔴 超 12 镜应已拆为 P0X.A + P0X.B（衔接字段套用）

            违反任 1 条 → FAIL

        [时长约束]（一票否决 · v8.0 升级为动态约束）

            🔴 审核前先读 .project-config.json.video_model_config.max_seconds（硬约束上限，默认 15s）
            🔴 每个 Cut 时长 ≥ 1.2 秒（绝对最低）
            🔴 每个 Cut 时长 ≤ max_seconds（从配置文件读取，不得超过）
            🔴 单 P0X 总时长 ≈ max_seconds ± 2 秒（随模型升级动态变化）
            🔴 时长写到 0.1 秒精度
            🔴 如 .project-config.json 缺 video_model_config → FAIL，提示分镜师先执行 ~video-model 配置

            违反任 1 条 → FAIL

        [其余审核维度同 [单条提示词通用质量审核]]

[单镜模式验收清单]（沿用 v6.1 + v7.0 微调）

    [素材对应表]（整体检查，不评分，但有错误直接 FAIL）

        完整性：是否为所有引用的素材建立了对应关系？
        准确性：素材描述是否与 `assets/visual/*.md` 一致？
        无孤立引用：提示词中的 @ 引用是否都在对应表中有记录？
        素材边界正确：对应表是否只包含在 assets/visual/*.md 中有参考图的素材？群演/一次性配角不应出现在对应表中。
        🔴 **场景独立编号（重要）**：scene-prompts.md 中的九宫格是生成格式，每场景必须独立编号为一个 @图片。如果发现整张九宫格被作为一个 @图片，**严重错误，FAIL**。
        引用用途明确：每个 @ 引用是否标注了用途？
        平台约束合规（单条维度）：图片 ≤ 9、视频 ≤ 3、音频 ≤ 3、总文件 ≤ 12。

    [群演/一次性配角处理]（整体检查，不评分）

        导演讲戏本中提到但不在 `character-prompts.md` 中的人物，是否用文字直接描述外观？
        这些人物是否错误使用了 @ 引用？（不应使用）
        文字描述是否够具体？

    [Cut 编号规范]（v7.0 新增，一票否决）

        🔴 单镜模式同样适用 Cut 1-N 编号（不用旧的 P<X>.<n>）
        🔴 默认 5-8 镜，上限 12 镜

    [时长约束]（v7.0 新增，v8.0 升级为动态约束，一票否决）

        🔴 同故事板模式：先读 .project-config.json.video_model_config.max_seconds
        🔴 每个 Cut 时长 ≥ 1.2 秒
        🔴 每个 Cut 时长 ≤ max_seconds（硬约束，默认 15s）
        🔴 单 P0X 总时长 ≈ max_seconds ± 2 秒

    [衔接字段]（v7.0 新增）

        每个 Cut 的「承接」字段是否填写？
        跨 P0X 的 Cut（如 Cut 6 是 P01 末，Cut 7 是 P02 首）是否有显式衔接（5 维度信息）？
        微观衔接 5 招（同道具 / 同光影 / 同色调 / 对白回环 / 情绪温度）是否在描述中体现？

[单条提示词通用质量审核]（双模式共用，每条 1-10 评分）

    忠实度（逐句比对）：将导演阐述和提示词逐句对照，核心动作、台词、镜头运动、光影描述是否完整保留？

    画面还原度（脑内预演）：想象 Seedance 生成的视频，是否与导演讲戏本中描述的画面一致？

    动作可执行性（脑内预演）：每个连续镜头内的动作/运动密度是否合理？多镜头段落的动作是否合理分配？是否存在动作跳跃？

    镜头可实现性（脑内预演）：镜头运动是否连续可实现？切换方式是否清晰？是否有物理上矛盾的要求？

    Seedance 友好度：是否采用叙事描述式（而非关键词堆叠）？是否有否定句？是否有重复静态内容？是否有可能让 Seedance 困惑的歧义表达？

    音频设计（含「严禁背景音乐」硬检查）：
    - 是否包含**环境音 + 动作音效**？描述是否与画面情绪匹配？台词是否标注语气？**完全缺失音频设计要扣分**。
    - 🔴 **硬检查（一票否决）**：搜索关键词「音乐 / BGM / 配乐 / 主题曲 / 旋律 / 背景音 / 钢琴响起 / 弦乐响起」，如果在提示词正文（不是元数据 / 不是故事板的 M5 模块）中找到任何一个，**该条直接 FAIL**。原因：用户后期会贴音乐总监设计的原创/市面音乐，视频自带 BGM 会和后配音乐双轨冲突。允许位置：仅可出现在「音乐编号」字段（标记后期 M01/M02）+ 故事板的 M5 底部辅助声音设计模块（视觉信息，不进 Seedance 视频生成），不可出现在视频提示词正文中。

    情绪准确性：传达的情绪基调是否与导演讲戏本中该剧情点的核心情绪一致？

[episode-master.md 验收清单]（v7.0 强制要求，双模式都审）

    [完整性]（一票否决）

        🔴 7 段必须齐全：本集基本信息 / 全片衔接表 / 故事板提示词表（仅故事板模式） / 视频提示词表 / 资产清单 / 音乐编号对应 / 用户操作清单
        🔴 故事板模式必填 §三、单镜模式跳过 §三
        🔴 §一基本信息字段齐全（项目 / 集数 / 总时长 / 模式 / 故事板风格 / settings 各字段 / 资产总锚 / 上一集衔接）

        缺任 1 段 → FAIL

    [全片衔接表完整性]（一票否决）

        🔴 表内每个 P0X 都有：上段衔接 / 故事板缩略 / 下段衔接 / 风险列
        🔴 风险列主动评估（不要默认填 `-`，应明确标 ⚠ 或确认无风险）
        🔴 首段「上段衔接」填「无（开场）」、末段「下段衔接」填「无（结尾）」

    [资产清单准确性]（不评分，错误点名）

        §五是否列出本集用到的所有 @ 引用编号？
        是否区分「跨集复用」与「仅本集」？
        故事板模式是否列出 §5.4 万能故事板 PNG 路径？

    [跨集衔接备注]（仅续集项目）

        §九是否列出沿用上一集的内容？
        是否给下一集留了衔接提示？

[整体连贯性]（整体评估，不单独评分，但影响最终判定）

    ⚠️ 审核范围：本段评判**提示词文本层面的过渡设计**——审核员读完所有提示词文本能否在脑中产生连贯画面。**不审核** Seedance 实际生成视频的帧像素是否对齐。

    衔接自然（设计层）：按顺序读完所有提示词，相邻两条**在文本描述层面**是否做了过渡设计？检查清单：
    - ✅ 上一条结尾的视觉锚点（道具特写 / 关键物件）是否在下一条开头被呼应？
    - ✅ 上一条的光影方向描述是否在下一条延续？
    - ✅ 上一条的色调描述是否在下一条延续？
    - ✅ 上一条结尾的台词是否在下一条开头有回响 / 引用 / 回应？
    - ✅ 上一条的情绪温度是否在下一条开场有自然延续？
    - ✅ from_previous + to_next 字段是否真正映射到了视觉描述（而不是空填）？
    - 严重问题：相邻两条**完全没有任何呼应描述**（不是缺一两项，而是 0 呼应）→ 在问题摘要中点名

    节奏合理：整体节奏是否有起伏？是否多条节奏雷同导致观感疲劳？

    情绪弧线：全部串联起来，情绪弧线是否与导演叙事设计一致？

    风格统一：全篇提示词写法风格、详略程度、[项目视觉风格] 段是否一致？

    光影/色调描述连续：相邻场景之间的光影/色调描述文字是否自洽？

    跳跃风险已标记：episode-master.md §二的风险列是否真正反映了潜在跳跃？（⚠ 时间/空间/情绪/角色/道具消失）
